# المخرَج المتوقَّع لـ 01_security_anon.sql

المخرَج **المتوقَّع** لنظامٍ سليم هو «رُفض» في الصفوف الأربعة الأولى.
أمّا **الفعليّ** عند الاستخراج (2026-10-06) فهو:

| الفحص | النتيجة |
|---|---|
| anon · v2_opp_open | نفذ: true |
| anon · v2_setting_rows(مدرسة=null) | نفذ: 6 صفًّا |
| غريب موثَّق · v2_opp_open | نفذ: true |
| غريب موثَّق · v2_setting_rows(null) | رُفض: تكليفك (بلا تكليف) لا يملك قراءة إعدادات المدرسة… |
| الإعداد المقروء | class_sections |
| كلُّ صفوفه في القاعدة | 6 صفًّا من 2 مدارس |

## السبب (من الكود المستخرَج)
- `v2.assert_role` يبدأ بـ `if auth.uid() is null then return;`، فلا يعترض anon.
- `v2_opp_open` يكتفي بـ `seat is null and v2.my_grant() not in ('owner','admin')`. وعند غياب الحساب تكون `my_grant()` قيمةً null، فيصير الشرط null ولا يُرفع الاستثناء، لا لـ anon ولا للموثَّق الغريب.
- `v2_setting_rows` مع `p_school = null` لا يقيّد بمدرسة، فيقرأ anon صفوف المدرستين كلتيهما.
- `grants.sql` يمنح EXECUTE لـ anon على هذه الجسور.

القاعدة لم تُعدَّل. هذا الملفّ بلاغٌ موثَّق لا إصلاح.
